## 최신 사용자 요청: 페이지 실행 BAT
- 생성 파일: `E:/harnes/network-path-inspector/start_npi.bat`.
- 위치와 무관하게 `%~dp0ui`를 기준으로 실행. Node PATH가 없으면 설치된 Hermes Node를 현재 프로세스 PATH에만 추가한다. 의존성 자동 설치나 OS 설정 변경은 하지 않는다.
- 기본 동작: `call npm.cmd run dev -- --host 127.0.0.1 --port 39201 --strictPort --open`. Vite 준비 후 기본 브라우저를 열도록 설정. 콘솔을 유지하며 Ctrl+C로 종료한다.
- `--check`: 준비 상태·실제 포트 바인딩 가능 여부 검사. `--no-browser`: 브라우저 없이 서버 시작. 포트 사용 중에는 다른 서버로 임의 연결하지 않고 실패한다.
- `tools/verify_page_launcher.py` 실제 CMD 검증 4/4통과: 준비 검사, 잘못된 인자 거부, 점유 포트 거부, 프로젝트와 무관한 cwd에서 무인자 기본 실행 후 HTML/App.tsx 실제HTTP200. Node가 없는 PATH에서 fallback도 검증. BAT 바이트 CRLF 확인.
- QA는 BROWSER=none으로 데스크톱 브라우저 열기만 억제했다. 화면 클릭/렌더링 재검증을 주장하지 않는다. 검증 소유 프로세스 트리만 종료하고 포트 닫힘을 확인했다.
- 기록: `artifacts/page-launcher-verification.json`, `artifacts/page-launcher-live.log`.
- 이 BAT는 현재 React 개발 프로토타입을 연다. 실제 진단 엔진·Session·native UI 연결 완료가 아니다.

## 개발 재개 중 확인한 별도 상태
- g2wire 격리 QA의 include_str 원본 fixture 배치를 바로잡았고 기본 시험·strict Clippy가 통과했다. 제품 코드를 바꾸지 않고 원본 바이트를 격리 경로에 복사했다.
- `g2wire-isolated-real-resume`: 실제localhost/루프백17개 통과. `NPI_TEST_HELPER_EXE`를 실제 제품 QA 바이너리 절대 경로로 명시했다. 프로필 엔진의 도메인 처리·Session·UI 연결 완료가 아니다.
- `g2verify` 프롬프트 2개를 작성했으나 사용자 BAT 요청으로 전환하기 전 실행 명령을 호출하지 않았다. 따라서 새 writer가 시작됐다고 주장하지 않는다.
- 남은 좁은 보정: DNS 명시시험에서 NPI_TEST_HELPER_EXE 미설정 시 조용한 return을 fail-closed로 변경; 가이드의 절대 worktree 링크·순서·ICMP 블로킹 설명·역사 snapshot 표기 수정. 전용 worktree의 기존 변경은 보존 커밋으로 보관했다.
- 통합 root는 여전히 G2 미완료·미커밋 변경 상태. 운영망/DB/정책/드라이버 변경·배포·원격 push 없음.
