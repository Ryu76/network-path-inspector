## 1. 개요 및 추적 원칙

본 문서는 Part B Network Quick Check의 13개 필수 요구사항(Q-P0-01 ~ Q-P0-13)에 대한 설계 반영, 현시점 상태 및 향후 검증 계획을 추적합니다.

### 1.1 상태 분류 기준 (엄격한 정직성 원칙)
- **`not-started`**: 구현 코드가 아직 작성되지 않았으며 계획 수립 단계임.
- **`partial`**: 기존 `npi-core`/`npi-probes`에 일부 기초 로직이 존재하나, Quick Check 단일 바이너리/GUI/Facade에 완전히 통합되지 않았음.
- **`blocked`**: 실제 외부 환경(깨끗한 VM, 2개 서로 다른 VLAN, 실제 패킷 DROP 라우터 등)의 부재로 인해 검증이 보류됨.
- **금지 사항**: 현재 QG0 설계 단계에서는 실행 가능한 Quick Check 바이너리 및 GUI가 존재하지 않으므로, **어떠한 항목도 `implemented` 또는 `통과(passed)`로 표시하지 않습니다**.

## 4. 환경 제약 및 블로커 관리 대장

현재 단계에서 검증을 차단하는 외부 환경 요소와 관리 지침은 다음과 같습니다:

1. **깨끗한 Windows VM 환경 (Clean VM)**:
   - 사유: Q-P0-01 무설치 단일 EXE 검증을 위해서는 개발 도구(Visual Studio, Rust, Git)나 C++ 재배포 패키지가 설치되지 않은 순정 Windows VM이 필요함.
   - 관리 지침: VM 준비 전까지 Q-P0-01의 최종 수용 검증은 `blocked`로 유지하며, 개발 환경에서의 성공을 VM 수용으로 간주하지 않음.
2. **실제 방화벽 DROP 및 ICMP 차단 환경**:
   - 사유: Q-P0-03 타임아웃 및 Q-P0-04 ICMP 차단 시의 동작을 실제 패킷 드롭 네트워크에서 검증해야 함.
   - 관리 지침: 임의로 로컬 윈도우 방화벽 규칙을 스크립트로 조작하여 인위적으로 통과시키지 않으며, 실험실 환경이 확보되지 않은 경우 모의 소켓 테스트로 한정하고 상태를 기록함.
3. **2개 서로 다른 VLAN 환경**:
   - 사유: 라우터를 경유하는 다중 홉 Traceroute 및 경로 검증 필요.
   - 관리 지침: 실제 복수 VLAN 환경 구축 전까지 Traceroute 종합 수용 테스트는 `blocked`로 유지.
