### ADR-001: 대상 플랫폼, 아키텍처 및 개발시험 환경 범위

- **상태**: 승인됨 (QG0)
- **맥락**: PRD에서는 Windows 10/11 및 Windows Server 2016 이상을 잠재적 수용 대상으로 언급하고 있으나, 모든 버전과 CPU 아키텍처에 대한 즉각적인 지원을 보장하는 것은 테스트 자원과 바이너리 호환성 측면에서 불가능합니다.
- **결정**:
  1. **초기 타깃 아키텍처**: `x86_64-pc-windows-msvc` (x64)로 한정합니다. ARM64(`aarch64-pc-windows-msvc`) 지원은 별도 타깃으로 분류하고 초기 지원 대상에서 보류합니다.
  2. **실제 개발시험 환경**: 현재 개발 및 하네스 검증 환경인 **Windows 10 빌드 19045 (x64)**로 한정합니다.
  3. **수용 대상 후보(Candidate) 명시**: Windows 10, Windows 11, Windows Server 2016 이상은 "PRD 수용 대상 후보"일 뿐이며, 실제 해당 OS VM 환경에서 검증되기 전까지는 "지원 보장"으로 표시하지 않습니다.

### ADR-002: 네이티브 Win32 GUI 라이브러리 선정 및 웹뷰 배제

- **상태**: 승인됨 (QG0)
- **맥락**: Quick Check는 외부 런타임(Edge WebView2, Node, GTK, Qt 등)이 설치되지 않은 환경에서도 즉시 구동되어야 하는 단일 무설치 바이너리를 목표로 합니다.
- **결정**:
  1. **Win32 API 직접 사용 우선**: 기존 `crates/npi-probes`에서 이미 사용 중인 `windows-sys`의 Win32 서브시스템 API(`Win32_UI_WindowsAndMessaging`, `Win32_Graphics_Gdi` 등)를 직접 활용하여 경량 네이티브 GUI를 구성하는 방식을 최우선으로 검토합니다.
  2. **런타임 의존성 배제**: Tauri, Electron, Qt, GTK, Slint, Iced 등 추가적인 C++ 런타임 DLL이나 웹뷰를 요구하는 프레임워크는 전면 배제합니다.
  3. **단일 EXE 검증**: 최종 지원 및 단일 EXE 가능 여부는 추후 Release PE Import 테이블 분석과 깨끗한 VM 환경에서의 실행으로 최종 판정합니다.

### ADR-003: 권한 모델 (asInvoker) 및 무설치/시스템 무변경 원칙

- **상태**: 승인됨 (QG0)
- **맥락**: 네트워크 진단 도구가 관리자 권한을 요구하거나 시스템 설정을 변경하면 운영 환경에서 심각한 보안 이슈를 유발합니다.
- **결정**:
  1. **일반 사용자 권한 전용**: 애플리케이션 매니페스트에 `<requestedExecutionLevel level="asInvoker"/>`를 설정하여 UAC 승격 창 없이 일반 사용자 권한으로만 실행되도록 강제합니다.
  2. **시스템 무변경 (Zero Mutation)**: OS 서비스 등록 0건, 레지스트리 키 수정 0건, Windows 방화벽 인바운드/아웃바운드 규칙 변경 0건, OS 라우팅 테이블 변경 0건, 인증서 저장소 변경 0건을 엄격히 준수합니다.

### ADR-004: CRT 정적 링크 검토 및 OS 시스템 DLL 경계

- **상태**: 승인됨 (QG0)
- **맥락**: 대상 PC에 최신 Visual C++ 재배포 패키지(`vcruntime140.dll` 등)가 설치되어 있지 않을 경우 실행이 실패할 수 있습니다.
- **결정**:
  1. **CRT 정적 링크 검토**: MSVC 컴파일러 플래그(`/MT`)를 통한 C 런타임 정적 링크(`target-feature=+crt-static`)를 검토합니다.
  2. **OS 시스템 DLL 경계 명문화**: "CRT 정적 링크"가 "OS 시스템 DLL 의존성 0개"를 의미하는 것이 아님을 명확히 합니다. Windows 기본 시스템 DLL(`kernel32.dll`, `user32.dll`, `ws2_32.dll`, `iphlpapi.dll` 등)은 OS가 기본 제공하는 컴포넌트이므로 정상적으로 동적 링크를 허용합니다.

### ADR-005: crates/network-core Facade 설계 및 기존 코드 재사용

- **상태**: 승인됨 (QG0)
- **맥락**: Quick Check와 Inspector는 동일한 진단 알고리즘을 공유해야 하며, 중복 구현이나 기존 Inspector의 코드 파손을 방지해야 합니다.
- **결정**:
  1. **Facade 라이브러리 도입**: 신규 `crates/network-core`를 생성하여 기존 `crates/npi-core`와 `crates/npi-probes`의 기능을 래핑하고, `qg1-contract.json`에 맞춘 데이터 모델을 제공합니다.
  2. **중복 코드 작성 금지**: TCP 소켓 연결, ICMP 핑, 어댑터 조회 로직을 Quick Check 앱에 복사하지 않고 반드시 공용 코어 구현을 재사용합니다.
  3. **기존 앱 분리 상태 명시**: 실제 Inspector 역시 공용 코어를 사용하도록 전환될 예정이지만, 현재 시점에서는 **물리적 추출 및 기존 앱의 새 facade 전환이 아직 이루어지지 않았음(Not yet migrated/extracted)**을 명확히 기록합니다.

### ADR-006: 진단 상한, 안전한 기본값 및 스캔 기능 원천 배제

- **상태**: 승인됨 (QG0)
- **맥락**: 진단 도구가 사내망 스캔이나 서비스 거부 공격 도구로 오용되는 것을 방지해야 합니다.
- **결정**:
  1. **계약 수치 준수**: [.harness/references/qg1-contract.json](file:///E:/harnes/network-path-inspector/.harness/references/qg1-contract.json)에 따라 최대 대상 수 100건(`max_targets: 100`), 기본 동시성 4 및 상한 4(`default_concurrency: 4`, `max_concurrency: 4`), 기본 TCP 타임아웃 3,000ms를 강제합니다.
  2. **기본 기능**: 기본 검사로 `tcp_connect` 및 `icmp_ping` 2개만 활성화하고, Traceroute는 기본 비활성화(OFF)합니다.
  3. **스캔 기능 배제**: 서브넷 대역(CIDR) 스캔 및 포트 범위(Port Range) 스캔 코드는 0건으로 배제하며, 사용자가 명시한 대상 목록만 순차/병렬(최대 4개) 처리합니다.

### ADR-007: 도메인 필수 해석 전제 관계 및 상세 DNS 검사 분리

- **상태**: 승인됨 (QG0)
- **맥락**: 사용자가 IP 대신 도메인(FQDN)을 입력한 경우 소켓 통신을 위해 IP 주소 해석이 필수적이지만, 이를 사용자가 명시적으로 선택하지 않은 "상세 DNS 진단"과 혼동해서는 안 됩니다.
- **결정**:
  1. **전제 관계 명문화**: 도메인 목적지의 경우 TCP 연결 수립을 위한 필수적인 시스템 리졸버 호출(A/AAAA 조회)을 내부 전제 조건으로 수행하며, 이를 `resolved_ip` 필드에 기록합니다.
  2. **기능별 미선택 원칙 준수**: 사용자가 `dns_lookup` 체크박스를 선택하지 않은 경우, 부가적인 DNS 레코드 질의나 지연시간 측정은 일체 수행하지 않습니다(미선택 실행 0회).
  3. **OS 리졸버 상태 한계 고지**: 현재 `npi-probes`에 존재하는 주소 확인 헬퍼는 개발용 루프백(`127.0.0.1`, `localhost`)에 한정되어 있으므로, "생산용 비루프백 DNS 리졸버가 이미 완료되었다"고 주장하지 않으며 QG2 구현 과제로 분류합니다.

### ADR-008: 비동기 스레딩, UI 비차단 및 취소 레이턴시 한계

- **상태**: 승인됨 (QG0)
- **맥락**: UI 스레드에서 네트워크 I/O를 수행하면 프로그램이 멈추며, 비동기 작업과 동기 API의 취소 특성이 다릅니다.
- **결정**:
  1. **UI 스레드 네트워크 I/O 0건**: 메인 UI 스레드는 윈도우 메시지 루프만 처리하고, 모든 소켓 및 네트워크 API는 백그라운드 워커(Tokio)에서 수행합니다.
  2. **취소 레이턴시 설계 목표와 실제 제약 구분**: "취소 후 3초 이내 자원 정리"는 실측 전 설계 목표일 뿐입니다. 비동기 TCP는 수십 밀리초 이내 즉각 취소되지만, Windows 동기 API인 `IcmpSendEcho2`는 API 내부에서 최대 2초(`clamp(1, 2000)`) 동안 블로킹될 수 있는 물리적 한계가 존재함을 인정하고 명시합니다.

### ADR-009: qg1-contract 데이터 스키마 준수 및 상태 매핑

- **상태**: 승인됨 (QG0)
- **맥락**: Quick Check는 복잡한 계층형 Session 1.1 구조 대신 경량 단일 레코드 스키마(schema 1.0)를 따르며, 오류 분류를 왜곡 없이 보존해야 합니다.
- **결정**:
  1. **고정 계약 준수**: [.harness/references/qg1-contract.json](file:///E:/harnes/network-path-inspector/.harness/references/qg1-contract.json)의 14개 필드와 열거형 값을 단일 진실 공급원으로 준수합니다.
  2. **상태 매핑**: `CANCELLED`는 `UNKNOWN/UNKNOWN`, `LOCAL_ERROR`는 `UNKNOWN/OBSERVED`로 매핑하며, 원본 소켓 에러코드(`os_error_code`) 및 에러 메시지는 `details` 객체에 보존합니다.
  3. **어댑터 분리**: Inspector에서 Quick Check의 결과를 통합 조회할 수 있는 JSON 변환 어댑터는 P1(후속 요구사항)으로 분리합니다.
  4. **미확인 값 null 보존**: 외부 사실이나 성능 수치를 날조하지 않고 미확인 필드는 `null`로 유지합니다.

### ADR-010: 결과 파일 보안, 원자적 쓰기 및 CSV 수식 주입 방어

- **상태**: 승인됨 (QG0)
- **맥락**: 로컬 파일 저장 및 클립보드 복사 시 데이터 훼손이나 스프레드시트 수식 실행 취약점이 발생할 수 있습니다.
- **결정**:
  1. **자동 저장/업로드 0건**: 사용자의 명시적인 저장 명령이 있을 때만 파일 다이얼로그를 통해 지정된 경로에 저장합니다.
  2. **원자적 파일 교체**: 임시 파일 작성 후 `ReplaceFile` 또는 `fs::rename`으로 교체하여 쓰기 도중 충돌을 방지합니다.
  3. **CSV Injection 방어**: CSV 텍스트 필드가 `=`, `+`, `-`, `@`, `\t`, `\r`로 시작할 경우 반드시 선행 단일 따옴표(`'`)를 추가합니다.
  4. **사내망 정보 노출 경고**: 공유 전 경고 팝업을 제공하고, 민감 IP 마스킹은 P1 옵션으로 테스트 계획을 수립합니다.

### ADR-011: 환경 부재 시 blocked 상태 보존 원칙

- **상태**: 승인됨 (QG0)
- **맥락**: 실제 방화벽 DROP, ICMP 차단 장비, 깨끗한 VM, 복수 VLAN 환경이 없는 상태에서 테스트를 강제로 통과시키기 위해 로컬 OS 방화벽을 변경하는 등의 위험한 작업이 발생할 수 있습니다.
- **결정**:
  1. **OS 정책 변경 금지**: 테스트 통과를 목적으로 로컬 Windows 방화벽 규칙, 라우트, DNS 캐시 등을 조작하지 않습니다.
  2. **blocked 상태 기록**: 필수 외부 환경이 준비되지 않은 경우 해당 테스트 항목을 정직하게 `blocked` 상태로 유지하고 블로커 사유를 기록합니다.

### ADR-012: 의존성 전이 감사 및 외부 라이브러리 거버넌스

- **상태**: 승인됨 (QG0)
- **맥락**: 새로운 외부 라이브러리 도입으로 인해 바이너리 크기 증가, 라이선스 위반, 보안 취약점 전이가 발생할 수 있습니다.
- **결정**:
  1. **새로운 의존성 승인제**: 신규 크레이트 추가 시 반드시 부모 에이전트의 승인을 득하고 도입 이유 및 보안 영향을 문서화합니다.
  2. **금지 의존성 전이 검사**: WebView2, Npcap, Agent, PDF, SQLite, 브라우저 엔진이 바이너리에 포함되지 않도록 빌드 파이프라인에서 `cargo tree` 검사를 의무화합니다.
  3. **보안 정책 준수**: 상용 라이선스 제약이나 사내 앱 실행 차단 정책(AppLocker 등)을 우회하려는 기법을 일체 금지합니다.
