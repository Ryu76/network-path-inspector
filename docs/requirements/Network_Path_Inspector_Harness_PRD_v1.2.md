# Network Path Inspector — Harness PRD

- 문서 버전: 1.2.0
- 작성일: 2026-10-21
- 상태: v1.1 유지 + 무설치 Network Quick Check 별도 제품 요구사항 반영 / 구현 전 검토 필요
- 제품 형태: 공통 Rust Core 기반 2종 제품 — Network Path Inspector(정밀 진단), Network Quick Check(무설치 단일 EXE)
- 핵심 원칙: **측정 사실·추론·확인 불가를 엄격히 구분하고, 증거 없이 특정 장비의 차단을 단정하지 않는다.**

## 1. 목적과 성공 기준

### 1.1 문제
서로 다른 사설망/VLAN 사이에서 방화벽 업체는 허용 정책 적용을 주장하지만 실제 TCP 연결은 실패한다. 기존 telnet/tcping 결과만으로는 요청 송신, 서버 수신, 응답, 반환 경로를 입증하기 어렵다.

### 1.2 목표
1. 이용자 PC **한 대만으로** 대상 IP:포트에 대한 가능한 범위의 네트워크 진단과 증빙을 수행한다.
2. 서버에도 설치할 수 있을 때 **양쪽 관측 자료를 비교**하여 장애 구간을 좁힌다.
3. 업체에 전달할 **재현 가능한 PDF 보고서 + 원본 PCAP/로그/JSON**을 생성한다.
4. 통신이 끊겨도 **오프라인 결과 파일 병합**이 가능해야 한다.
5. 운영 환경의 DB·네트워크 정책을 변경하지 않고 **읽기·측정 중심**으로 동작한다.

### 1.3 성공 기준(수용 기준)
- 단독 모드: 입력한 IP/도메인 및 TCP 포트로 연결 성공·거부·시간초과·라우팅 오류 등을 분류하고 원본 측정값 저장.
- 양방향 모드: 동일 진단 세션의 송수신 증거를 시간·5-tuple·NAT 가능성에 따라 상호 비교.
- 보고서: 출발지/목적지, 프로토콜, 시각(시간대), 시도별 결과, 로컬 환경, 경로 응답, 근거 파일, 불확실성, 업체 요청사항 포함.
- 패킷 캡처 드라이버가 없거나 권한이 부족해도 기본 TCP·라우팅 진단은 작동하고 제한사항을 표시.
- 측정 결과로 **차단 지점 확정** 문구를 자동 생성하지 않음(방화벽 로그/해당 장비 캡처 등 별도 증거 없으면).

## 2. 범위

### 2.1 필수 기능(P0)
| ID | 요구사항 | 수용 기준 |
|---|---|---|
| P0-01 | 단독 진단 | 한 PC에서 목적지 IPv4/IPv6·도메인, TCP 포트, 타임아웃 입력 후 검사 가능 |
| P0-02 | TCP Connect | 연결 성공/거부/시간초과/네트워크·호스트 도달 불가/로컬 오류 분류; 소켓 오류코드 기록 |
| P0-03 | ICMP Ping | 응답 시간, 손실, ICMP 비응답과 TCP 실패를 구별 |
| P0-04 | 경로 추적 | ICMP 경로 추적 + 가능 시 TCP TTL 프로브; 각 HOP의 응답/비응답과 방법 명시 |
| P0-05 | 네트워크 상태 | 로컬 IP, NIC, 게이트웨이, DNS, 라우팅 테이블, 선택된 출발지 인터페이스 수집 |
| P0-06 | 로컬 리스닝 확인 | 서버 설치 시 대상 포트 LISTENING 여부·바인딩 주소·PID 확인 |
| P0-07 | 선택적 패킷 캡처 | Npcap 설치·권한 확인, 테스트 관련 패킷 필터링, PCAPNG/PCAP 저장, 실패 시 명확한 안내 |
| P0-08 | 양방향 진단 | 양측 동일 세션 ID를 사용하여 캡처/진단 결과 비교 |
| P0-09 | 오프라인 병합 | 서버/클라이언트 결과 ZIP을 파일로 가져와 분석, 실시간 직접 통신 불필요 |
| P0-10 | 보고서 | PDF + 기계 판독 JSON + 원본 로그/캡처 + SHA-256 목록을 ZIP으로 출력 |
| P0-11 | 근거 수준 | Observed / Inferred / Unknown 표시, '마지막 응답 HOP=차단 장비' 금지 |
| P0-12 | 방화벽 정책 검증 | 출발지·목적지·포트·프로토콜·업체 허용 통보 메모와 실제 측정 결과 비교 |
| P0-13 | 비파괴 운영 | Oracle 인증/SQL 수행 불필요; TCP 핸드셰이크만으로 검사 가능 |

### 2.2 후속 기능(P1)
- 주기적 TCP 모니터링, 실패 시 자동 증거 저장(순환 버퍼를 미리 시작한 경우만 실패 이전 패킷 보존 가능).
- 네트워크 구성 변경 감지(주소/게이트웨이/NIC/라우트/DNS).
- 시각적 HOP 타임라인, 테스트 이력 검색, CSV 내보내기.
- 동일 환경의 테스트 프로파일 저장·불러오기.
- 온라인 양방향 협업: 별도 승인된 관리 서버를 경유한 결과 전달(기본 기능의 선행 조건 아님).

### 2.3 범위 제외
- 방화벽 정책 자동 변경, 서버 라우팅/방화벽 자동 수정, 네트워크 장비 로그인·로그 수집의 무단 자동화.
- 포트 스캔, 대량 부하 검사, 우회 연결, 취약점 검사.
- TCP 연결 성공을 Oracle 서비스 로그인 성공으로 해석하는 기능.
- 응답하지 않은 HOP을 차단 지점으로 확정하는 기능.

## 3. 사용 시나리오

### UC-01: 이용자 PC 단독 진단
1. 사용자가 `192.168.10.100:1526` 입력, '단독 진단' 선택.
2. 로컬 NIC/라우트/DNS → TCP 연결 → ICMP/TCP 경로 추적 → 선택적 캡처 실행.
3. 실패 유형과 마지막 응답 HOP을 표시하되, 확인 불가 구간으로 표시.
4. 증거 ZIP 및 PDF 생성.

### UC-02: 서버+이용자 PC 양방향 진단
1. 양쪽 프로그램에서 동일 세션 ID를 설정(또는 세션 파일 교환).
2. 각자 동일 테스트 시간대에 캡처 시작; 서버는 LISTENING과 로컬 방화벽 상태 수집.
3. 클라이언트가 TCP 연결 시도, 양쪽이 송신/수신 이벤트와 패킷 저장.
4. 오프라인 ZIP 병합 또는 승인된 협업 경로로 결과 전달.
5. SYN 송신·서버 수신·SYN-ACK 응답·클라이언트 수신 여부를 비교하여 관찰 결과와 가설 분리.

### UC-03: 업체 정책 허용 주장 검증
- 사용자 입력: 정책 요청 번호, 업체 회신 시간, 출발지/목적지 IP, 프로토콜/포트, 허용 통보 내용.
- 결과: '업체 통보: 허용 / 측정: TCP 실패'를 사실로 기록; 실제 차단 장비는 미확정으로 표시.
- 보고서에 방화벽 세션/정책 매칭/Drop 로그 확인 요청 문구 자동 포함.

## 4. 정확성·분석 규칙

### 4.1 TCP 결과 분류
- Connected: TCP 핸드셰이크 성공(Oracle 인증 성공을 의미하지 않음).
- Refused/RST: 거부 응답 확인(응답 생성 주체는 추가 검증 필요).
- Timeout: 제한시간 내 연결 수립 실패; 방화벽 차단으로 단정 금지.
- Unreachable: OS/ICMP에서 도달 불가 반환; 원본 코드와 메시지 보존.
- Local failure: 소켓 생성/권한/NIC/캡처 드라이버 오류를 원격 장애와 분리.

### 4.2 패킷 비교
- 세션 ID, UTC 타임스탬프, 로컬 시간대, 시계 오차 추정치, 프로토콜, 출발지/목적지 IP·포트, TCP 플래그, TCP 시퀀스 정보 등을 사용.
- NAT/프록시/비대칭 라우팅이 있으면 5-tuple 불일치를 허용하고 '매칭 불확실' 표시.
- 캡처 시작/종료 시각과 인터페이스·필터·패킷 드롭 통계를 기록.
- **서버에서 SYN 미관찰 = 서버 미도착 확정 아님**: 잘못된 NIC, 필터, 캡처 손실 가능성을 먼저 점검.
- Windows 방화벽 로그 '기록 없음' = 차단 없음이 아님.
- ICMP/TCP Traceroute 중간 응답 없음 = 해당 장비 차단 증명 아님.

### 4.3 판정 출력 스키마
각 판정은 `classification`(OBSERVED/INFERRED/UNKNOWN), `statement`, `evidence_ids[]`, `confidence`(low/medium/high), `limitations[]`, `next_checks[]`를 갖는다. OBSERVED는 원본 증거 참조가 필수.

## 5. UI/UX
- 상단: 단독 진단 / 양방향 진단 / 모니터링(후속).
- 입력: 대상 IP 또는 도메인, TCP 포트(1~65535), 타임아웃, 최대 HOP, 반복 횟수, 캡처 여부.
- 본문: 네트워크 경로 시각화, 테스트별 PASS/FAIL/WARN, 세부 로그, 증거 수준 배지.
- 하단: 진단 시작·중지, 원본 저장, PDF 생성, ZIP 내보내기, 결과 가져오기.
- 제한사항: Npcap 없음, 관리자 권한 없음, ICMP 차단, 서버 미설치 등을 눈에 띄게 표시.
- 색상만으로 판정 구별하지 않음; 텍스트와 아이콘 병행.

## 6. 시스템 아키텍처

### 6.1 기술 기준안
- Windows 10/11 및 Windows Server 2016 이상(지원 버전은 실제 테스트로 확정).
- Rust 진단 엔진 + Tokio 비동기 TCP, Tauri + React UI, SQLite 로컬 이력.
- Windows API: NIC/라우트/ICMP/포트 상태 수집. Npcap 선택적 캡처, pcap/etherparse 계열 파서.
- HTML 템플릿 → PDF, JSON Schema 검증, ZIP 증거 번들.
- 동일 설치 패키지에서 GUI 또는 제한된 Agent 모드 실행.

### 6.2 모듈
`ui`, `diagnostic-orchestrator`, `tcp-probe`, `icmp-probe`, `route-trace`, `host-inventory`, `packet-capture`, `evidence-normalizer`, `correlation-engine`, `report-builder`, `storage`, `security-policy`.

### 6.3 모드와 네트워크 의존성
- 단독: 외부 관리 서버 없이 작동.
- 양방향 오프라인: 양쪽 ZIP 파일만 있으면 병합.
- 온라인: 별도 관리 서버가 승인된 경우에만 사용. DB 서버에 새 인바운드 포트를 열도록 강제하지 않음.

```text
NPI_20261020_<session-id>.zip
```

- 원본과 정규화된 데이터는 분리 보관.
- 보고서에 수집 호스트·시각·툴 버전·캡처 필터·드롭 통계를 기재.

## 8. 보안·운영 정책
- 대상은 사용자가 명시적으로 입력한 승인된 시스템으로 제한; 임의 대역 자동 스캔 금지.
- 기본 진단은 일반 사용자 권한; 관리자 권한·Npcap은 필요한 기능에서만 요청.
- DB 비밀번호 및 계정 입력 금지. 민감 정보(IP/호스트명/패킷 페이로드)는 최소 수집·마스킹 옵션 제공.
- 캡처 기본값: 테스트 대상 IP/포트 중심 BPF 필터; 전체 트래픽 캡처는 명시적 승인 시에만.
- 저장 데이터는 로컬 우선, 보관 기간 설정, 사용자가 삭제 가능. 자동 업로드 금지.
- 보고서와 ZIP 내보내기 전 개인정보/내부망 정보 노출 경고.
- 캡처는 사용자 중지·타임아웃·앱 종료 시 반드시 해제.
- 서버 방화벽/Oracle Listener/레지스트리/라우팅 설정을 프로그램이 임의 변경하지 않음.

## 9. 성능·안정성 요구
- 기본 TCP 타임아웃 5초(설정 가능), 기본 경로 추적 최대 30 HOP(설정 가능).
- 동시 프로브 수·재시도 횟수 상한, 요청 간 간격 설정; 네트워크 부하 제한.
- 취소 시 모든 백그라운드 작업·캡처 세션 종료, 부분 결과는 '중단됨'으로 보존.
- 프로브 오류가 전체 프로그램을 종료시키지 않도록 작업 격리.
- 진단 세션은 유일 ID, 저장은 원자적 기록 및 충돌 방지.
- 시간 동기화 상태 및 양측 시계 오차를 보고서에 표시.

## 10. AI 하네스 개발 규칙

### 10.1 최우선 원칙
1. **관찰 가능한 동작과 진단 의미의 정확성** > 기능 수 > UI 미관 > 성능 최적화.
2. 원본 증거 없이 추정 결과를 '확정'으로 승격하지 않는다.
3. 테스트 실패를 무시·삭제·기대값 변경으로 우회하지 않는다.
4. 운영 DB/방화벽/네트워크 설정 변경은 자동화 작업의 권한 밖이다.
5. 기존 동작 변경은 사전 테스트 및 회귀 테스트 후 승인한다.

### 10.2 작업 순서(단계별 게이트)
- G0: 요구사항·위협 모델·지원 OS/권한·Npcap 설치 정책 확정.
- G1: 핵심 데이터 모델/오류 분류/JSON Schema 및 테스트 픽스처 작성.
- G2: TCP·NIC·라우트·ICMP 단독 진단 구현, 단위·통합 테스트 통과.
- G3: 경로 추적 구현, ICMP 비응답·TCP 성공 혼합 사례 검증.
- G4: 선택적 캡처 구현, 권한·드라이버 미설치·드롭 처리 검증.
- G5: 양방향 오프라인 병합·시계 오차·NAT·비대칭 경로 처리.
- G6: PDF·증거 ZIP 생성, 해시 검증·재현성 검사.
- G7: 실제 두 VLAN 실험실 테스트, 실패 케이스 회귀.
- G8: 서명/배포/설치·제거 검증 및 운영 체크리스트.
- **게이트 실패 시 다음 단계 진행 금지**; 원인과 보완 내역 기록.

### 10.3 테스트 정책
- Unit: 결과 분류, TTL/HOP 정규화, 시간 오차, 패킷 매칭, 오류 메시지.
- Characterization: Windows `Test-NetConnection`, `tracert`, `route print`, `netstat`와 가능한 범위에서 결과 대조; 불일치는 원인 기록.
- Golden Master: 고정 JSON/PCAP 샘플에서 기대 판정·보고서 필드 비교(시각 등 비결정 값은 정규화).
- Differential: 실제 네트워크 도구와 동일 조건으로 측정 비교; 도구 간 방법 차이를 명시.
- Fault injection: 캡처 권한 없음, Npcap 미설치, NIC 변경, RST, timeout, ICMP blocked, 패킷 드롭, NAT, 시간 오차, 중간 종료.
- Integration: 동일 VLAN 성공, VLAN 간 허용, VLAN ACL 차단, 서버 로컬 방화벽 차단, 서버 포트 미리스닝, 비대칭 경로.
- Negative: 캡처 미실행 상태에서 'SYN 송신 확인' 판정 금지; 미응답 HOP을 차단 장비로 판정 금지.

## 13. 경량화·최적화 설계 (v1.1 추가)

### 13.1 실행 정책
- **기본값은 최소 실행**: 앱 실행 시 패킷 캡처, Traceroute, PDF 렌더러, 모니터링 작업을 자동 시작하지 않는다.
- **On-demand / Lazy-load**: 기능을 선택했을 때만 모듈 초기화, 실행 종료·취소 시 핸들/소켓/버퍼 해제.
- **공유 Rust Core**: GUI와 Headless Agent가 동일 진단 라이브러리를 사용하고 UI 프로세스가 없어도 Agent 실행 가능.
- **비동기·동시성 제한**: Tokio 기반 작업 취소 토큰, 세마포어, 작업별 타임아웃, 제한된 재시도 및 백오프.
- **UI 갱신 분리**: 측정 이벤트는 큐로 전달하고 UI는 배치/스로틀 갱신(기본 최대 4회/초). 긴 로그는 가상 스크롤 사용.
- **스트리밍 저장**: 패킷/로그 전체를 메모리에 적재하지 않고 파일로 스트리밍, SQLite WAL 및 배치 쓰기.
- **저장 제한**: 기본 PCAP 최대 50 MiB/세션, 캡처 기본 30초, 로그 보관 30일(설정 가능). 한도 도달 시 캡처 종료·부분 증거 상태 기록; 원본 덮어쓰기 금지.
- **모니터링**: 기본 비활성화, 켜면 TCP 연결만 10초 간격. 장애 시 경량 진단 후 사용자 설정에 따라 정밀 진단. 실패 이전 패킷은 사전 순환 캡처가 활성화된 경우에만 확보 가능.
- **선택적 의존성**: Npcap 부재 시 TCP/ICMP/라우팅 기능 유지; PDF 생성 엔진은 보고서 생성 시에만 실행.
- **성능보다 정확성 우선**: 최적화로 타임아웃 의미, 패킷 누락 표기, 근거 분류, 결과 스키마를 변경하지 않는다.

### 13.2 초기 성능 목표(실측치 아님)
| 상황 | 목표 | 검증 방법 |
|---|---|---|
| GUI 유휴 | 메모리 80 MiB 이하, CPU 평균 1% 이하 | Windows 성능 카운터 10분 측정 |
| 단독 일반 진단 | 메모리 120 MiB 이하, CPU 평균 5% 이하 | TCP/ICMP/라우팅 시나리오 30회 |
| 정밀 캡처 | 메모리 200 MiB 이하(고트래픽 별도 프로파일) | 제한된 패킷 부하 및 드롭율 병기 |
| Headless Agent 유휴 | 메모리 30 MiB 이하, CPU 평균 1% 이하 | GUI 미실행 10분 측정 |

위 수치는 **목표 예산**이며 장비 사양, WebView2, Npcap, 네트워크 부하에 따라 조정할 수 있다. 하드웨어·OS·측정 조건을 고정해 P50/P95 및 최대치를 보고하고, 초과 시 최적화 또는 근거 있는 예외 승인 필요.

### 13.3 부하 보호
- 기본 동시 목적지 1개, 동시 TCP 프로브 최대 4개, 최대 HOP 30, 재시도 최대 3회(상한은 설정 및 테스트로 확정).
- 패킷 캡처는 기본 OFF, 대상 IP/포트 BPF 필터 기본 적용. 필터 해제는 경고 및 명시적 사용자 승인 필요.
- 정밀 진단 중 UI 종료, 시스템 절전, NIC 변경, 캡처 드롭/파일 용량 초과 시 부분 결과를 남기고 안전하게 종료.
- 자동 재시도는 운영 서버에 불필요한 트래픽을 유발하지 않도록 지터/백오프 적용.

## 14. 선택형 진단 및 기능별·그룹별 조회 (v1.1 추가)

### 14.1 기능 그룹 정의
| 그룹 ID | 그룹명 | 선택 가능한 기능 ID | 기본 선택 |
|---|---|---|---|
| G-NET | 기본 연결 | TCP Connect, ICMP Ping, DNS 조회 | TCP Connect, ICMP Ping |
| G-PATH | 경로·라우팅 | ICMP Traceroute, TCP Traceroute, 라우팅 테이블, NIC/게이트웨이 | NIC/게이트웨이, 라우팅 테이블 |
| G-PKT | 패킷·방화벽 | 선택적 패킷 캡처, SYN/RST 분석, 로컬 방화벽 로그, LISTENING 검사 | 없음 |
| G-PAIR | 양방향 비교 | Agent 세션, 결과 ZIP 가져오기, 패킷 비교, 시계 오차 검사 | 없음 |
| G-OPS | 운영·모니터링 | 반복 TCP, 변경 감지, 이력 조회 | 없음 |
| G-EVID | 증빙·보고 | 결과 JSON, PDF, PCAP 내보내기, 해시 검증, 정책 검증 | 결과 JSON |

그룹/기능 ID는 내부적으로 고정된 안정적 식별자를 사용하며 표시 이름만 현지화한다. 기능이 미지원/권한 부족/드라이버 미설치 상태이면 체크박스를 비활성화하고 이유 및 대안을 표시한다.

### 14.2 선택 UX
- **빠른 진단**: TCP + Ping + 로컬 네트워크 정보. 첫 실행 기본 프리셋.
- **경로 진단**: 빠른 진단 + ICMP/TCP Traceroute + 라우팅.
- **정밀 증빙**: 경로 진단 + 패킷 캡처(사용자 승인) + 방화벽/리스닝 점검 + 증빙 내보내기.
- **양방향 비교**: 양측 결과 수집/가져오기 및 비교. 서버 미설치 시 오프라인 병합 안내.
- **사용자 정의**: 그룹 전체 선택/해제, 그룹 펼침/접기, 기능별 개별 체크박스, 전체 선택/초기화, 검색 필터, 선택 항목 수·예상 소요시간 표시.
- 선택 상태를 프로파일로 저장/불러오기/복제할 수 있으며 최근 사용값은 복원하되 위험·고부하 기능은 자동 활성화하지 않는다.
- **그룹별 조회**: 검사 실행 전 그룹별 선택, 실행 후 그룹별 결과 집계(PASS/FAIL/WARN/SKIPPED/ERROR)와 펼침 상세 조회.
- **기능별 조회**: 기능별 측정값·시작/종료 시각·근거 수준·원본 로그·증거 파일·오류 코드·다음 점검 제안을 조회.
- **결과 필터**: 그룹, 기능, 상태, 호스트 역할(클라이언트/서버), 진단 모드, 세션, 기간, 대상 IP:포트, 근거 수준. 검색·정렬·CSV/JSON 내보내기 지원.
- 선택하지 않은 기능은 `SKIPPED_BY_USER`, 의존성 부족은 `UNAVAILABLE`, 실행 중 실패는 `ERROR`로 구분하며 미실행을 PASS/FAIL로 오인하지 않도록 한다.

### 14.3 실행 의존성 및 스케줄러
- 기능 레지스트리 필드: `feature_id`, `group_id`, `label`, `description`, `default_selected`, `requirements[]`, `dependencies[]`, `cost_class`, `permission_level`, `supported_modes[]`.
- 선택 기능을 DAG로 정렬해 **필요한 선행 수집만** 실행한다. 공통 NIC/라우트 조회는 세션당 1회 수집 후 공유.
- TCP Traceroute에 필요한 패킷 캡처·권한은 플랫폼 구현에 따라 검증하고, 불가하면 대체 검사로 전환하거나 미지원으로 기록. 조용히 ICMP 결과를 TCP 결과로 바꾸지 않는다.
- 기능 선택 변경은 실행 전에는 즉시 반영, 실행 중에는 다음 세션에만 반영(현재 세션 구성 스냅샷 고정).
- 기능별 타임아웃·취소·실패 격리; 하나의 기능 실패가 다른 독립 기능의 실행을 막지 않는다.
- 단독 모드에서도 그룹/기능별 조회가 완전하게 동작하며 양방향 모드에서만 추가 서버 데이터 열을 노출한다.

- 성능 회귀: 변경 전후 동일 PC·동일 테스트 세트의 RSS/CPU/P95 실행시간/패킷 드롭 비교. **정확성 회귀가 먼저 통과**해야 최적화 병합 가능.
- UI 회귀: 전체 선택/해제, 그룹 선택, 개별 선택, 검색 필터, 프리셋 저장, 그룹·기능별 조회, 빈 결과, 미지원 기능, 중간 취소 테스트.
- 안정성 회귀: 작업 취소·앱 종료 후 소켓/캡처 핸들 해제, 파일 크기 상한, 로그 로테이션, 장시간 누수 확인.
- 성능 목표 미달 시 측정값과 병목을 기록하고, AI 작업자가 임의로 기준치를 상향하거나 테스트를 삭제하지 않는다.

### 18.1 후속 요구사항 (P1)
- 5~10초 이상 사용자 지정 주기의 반복 TCP 검사, 성공률 및 장애 시각 기록.
- 검사 대상 목록 저장·불러오기(CSV/JSON); 최근 대상 및 사용자 프리셋.
- 검사 결과를 Inspector에서 읽을 수 있는 공통 JSON 스키마로 내보내기.
- 클립보드 다중 행 붙여넣기, 실패 결과만 복사, 정렬 및 검색.

### 18.2 명시적 제외
- Npcap/Raw Socket 기반 패킷 캡처, SYN 송신 확인 주장, 서버 패킷 수신 여부 분석.
- 양방향 Agent, 온라인 중계 서버, 자동 방화벽 규칙 수정, Oracle 로그인 검증.
- 자동 전체 포트 스캔/서브넷 스캔 및 네트워크 부하 시험.

## 19. UX 및 사용 흐름
1. 사용자가 `NetworkQuickCheck.exe`를 전달받아 더블클릭한다.
2. IP/도메인과 포트(예: `192.168.10.100:1526`)를 입력하거나 여러 행을 붙여넣는다.
3. 검사 기능 체크박스를 선택한다(기본 TCP + Ping; Traceroute는 기본 해제).
4. **검사 시작** → 대상별 상태/지연/오류/진행률 실시간 표시 → **중지** 가능.
5. 결과를 기능별·대상별·성공/실패별 필터링하고 복사 또는 TXT/CSV 저장.

```text
┌ Network Quick Check ──────────────────────────────────────────────────┐
│ 대상: [192.168.10.100] 포트: [1526] [대상 추가] [여러 건 붙여넣기] │
│ 기능: [✓]TCP [✓]Ping [ ]Traceroute [ ]DNS [ ]로컬 네트워크       │
│ 타임아웃 [3000ms]  동시 검사 [4]  [시작] [중지]                 │
├───────────────────────────────────────────────────────────────────────┤
│ 필터: [전체 ▼] [기능 ▼] [대상 검색...]                             │
│ 192.168.10.100:1526 | TCP | FAIL | TIMEOUT | 3001ms             │
│ 192.168.10.100      | Ping| PASS | 2ms                           │
├───────────────────────────────────────────────────────────────────────┤
│ [결과 복사] [TXT 저장] [CSV 저장] [상세 보기]                     │
└───────────────────────────────────────────────────────────────────────┘
```

## 20. 기술 구조 및 경량화

```text
network-diagnostic/ (Rust Workspace)
├── crates/network-core/          # TCP·Ping·DNS·라우트·결과 타입·판정 규칙
├── apps/network-inspector/       # 기존 Tauri GUI, 정밀 진단
├── apps/network-agent/           # 기존 헤드리스 양방향 Agent
└── apps/network-quick-check/     # 네이티브 Windows GUI, 단일 EXE
```

- Core는 GUI/파일 형식/캡처 드라이버와 분리하고 인터페이스로 의존성을 역전한다.
- 기본 검사는 비동기로 실행하며 UI 스레드에서 네트워크 I/O를 수행하지 않는다.
- 다중 대상 동시 실행 기본값 4, 사용자 설정 상한을 두고 무제한 동시 실행을 금지한다.
- Traceroute는 체크한 경우에만 실행; 자식 프로세스 사용 시 숨김 창·종료·타임아웃·출력 파싱 실패를 처리한다.
- DNS는 대상 주소가 도메인일 때 연결을 위한 필수 해석과 '상세 DNS 검사'를 구분한다.
- 검사 결과는 메모리 상한을 두고 화면에는 최근 항목만 유지; 대량 로그는 필요 시 스트리밍 저장한다.
- 패킷 캡처, PDF 렌더러, 브라우저 엔진, DB 엔진을 Quick Check 실행 파일에 포함하지 않는다.
- 단일 EXE 목표는 Windows 버전·빌드 도구·링크 방식에 따라 달라지므로 **깨끗한 VM에서 의존성 검사**를 수용 기준으로 삼는다.

### 20.1 초기 성능 목표(확정 전 측정 필요)
| 지표 | 초기 목표 | 검증 방법 |
|---|---|---|

| 유휴 메모리 | 30MB 이하 목표 | 작업 관리자/성능 카운터, 5분 안정화 |
| 유휴 CPU | 평균 1% 이하 | 5분 평균 측정 |
| 초기 화면 표시 | 1초 이내 목표 | 반복 30회 측정, PC 사양 기록 |
| TCP 기본 타임아웃 | 3초 | 강제 DROP 환경 테스트 |
| UI 응답 | 검사 중 조작 가능 | 100개 대상 테스트, UI 멈춤 없음 |
| 잔여 자원 | 취소/종료 후 누수 없음 | 핸들·프로세스·소켓 검사 |

수치는 설계 목표이며 보장값이 아니다. 최적화로 진단 정확성이나 오류 분류를 훼손하지 않는다.

## 21. 데이터 계약 및 증빙 수준
- 공통 필드: `schema_version`, `product`, `session_id`, `timestamp_iso8601`, `source_host`, `target_host`, `resolved_ip`, `target_port`, `feature`, `status`, `elapsed_ms`, `os_error_code`, `details`, `evidence_level`.
- 상태: `PASS`, `FAIL`, `WARN`, `SKIPPED`, `UNKNOWN`; 연결 오류 세부 사유는 별도 필드로 저장.
- 증거 수준: `OBSERVED`(실제 로컬 검사), `INFERRED`(근거 기반 추정), `UNKNOWN`(확인 불가).
- TXT/CSV 저장 시 검사 설정·대상·시각·시간대·프로그램 버전을 포함한다. CSV 셀은 스프레드시트 수식 주입을 방지한다.
- 외부 제출 시 로컬 IP·호스트명 등의 개인정보/내부망 정보 포함 여부를 사용자에게 안내한다.
- Inspector와 공유하는 스키마 변경 시 호환성 테스트 및 버전 관리가 필수다.

| QG7 | 성능·안정성·회귀 | 성능 측정 보고서 + Inspector/Quick Check 양쪽 회귀 통과 |

- AI 개발 작업자는 각 Gate에서 변경 파일, 테스트 명령, 실행 로그, 통과/실패, 알려진 제한을 기록한다.
- 실패 테스트 삭제/무시, 성능 목표 임의 완화, 허위 측정값 기재, 운영 방화벽 설정 자동 변경을 금지한다.
- TCP 연결 성공은 **해당 포트의 TCP 연결 성립**만 뜻하며 Oracle DB 기능 정상 여부를 의미하지 않는다.
- Traceroute 무응답 HOP을 차단 장비로 확정하거나 단독 검사에서 SYN 패킷 관찰을 주장하지 않는다.

## 23. 통합 수용 테스트 및 배포 산출물
1. VLAN이 다른 PC에서 허용·거부·DROP 조건을 재현하고 결과를 비교한다.
2. `localhost`, 실제 서버 IP, 다른 VLAN IP를 각각 검사하여 차이를 기록한다.
3. 도메인 다중 IP 해석, IPv6, DNS 실패, NIC 다중 장착, VPN, 잘못된 포트 입력을 테스트한다.
4. Quick Check의 결과를 Inspector와 비교해 같은 TCP 테스트의 판정 규칙이 일치하는지 확인한다.
5. 네트워크 단절 중에도 Quick Check가 종료되지 않고 결과 저장이 가능해야 한다.
6. 배포물: `NetworkQuickCheck.exe`, SHA-256 체크섬, 간단 사용 설명서, 테스트 결과표. 필요 시 별도 `NetworkPathInspector` 배포물.
7. 실행 파일에 코드 서명을 적용할 수 있도록 빌드 파이프라인을 설계한다. 조직의 앱 실행 차단 정책까지 우회하거나 무조건 실행을 보장하지 않는다.

## 24. 개발 전 확정할 항목
- Windows Server 최소 버전 및 x64/ARM64 지원 범위.
- 네이티브 GUI 라이브러리(예: `windows` API 직접 사용 또는 적절한 Rust GUI 프레임워크)와 단일 EXE 의존성 검증.
- 다중 대상 기본 상한 및 최대 대상 수, 반복 검사(P1) 포함 여부.
- Quick Check 결과 파일의 개인정보 마스킹 정책과 기본 저장 위치.

### v1.2 AI 개발 작업 지시문
> Part A(v1.1)의 Network Path Inspector 요구사항을 유지하면서 Part B의 Network Quick Check를 **별도 무설치 EXE 제품**으로 구현한다. 공통 network-core를 공유하되 Quick Check에는 Npcap·Agent·PDF·SQLite·웹뷰 의존성을 포함하지 않는다. 우선 QG0~QG1을 진행하고 기능 동등성 테스트를 확보한 뒤 QG2~QG7을 순차 수행한다. 선택한 검사만 실행하고, 단독 진단의 관측 한계를 명확히 표시한다. 운영 설정을 변경하지 않으며 테스트 실패를 우회하지 않는다. 성능 목표는 실제 측정으로 검증한다.
